# BASE2_REPORT — основа проекта Қаржы

Дата: 2026-11-02. Статус: основа и домен денег реализованы и проверены в среде разработки; **на физическом iPhone, в Safari и на боевом Cloudflare ничего не проверялось.**

## Что сделано
- **Ядро:** аккаунты (PBKDF2, блокировка после 5 попыток), сессии (хеш токена, cookie HttpOnly/Secure/SameSite=Strict, отзыв устройств, отзыв при смене пароля), ключи API `write`/`read` (хеш, показ один раз, метка, `last_used`, лимиты), идемпотентные записи, мягкое удаление, версии для конфликтов, миграции (`migrations/`), админ-скрипт (`add`, `set-password`, `list`, `revoke`, `disable`, `enable`, скрытый ввод пароля, проверка точного origin для `--remote`).
- **Домен денег:** записи (расход/доход), категории (создать/переименовать/перекрасить/удалить, стартовый набор), получатели с привязкой категории отдельно для расходов и доходов, правила по тексту, импорт CSV (сумма со знаком / две колонки / колонка типа), отчёт по каждой строке импорта, откат импорта, отчёты за месяц (по категориям и по получателям, количество и сумма), экспорт CSV.
- **«Команды»:** `POST /api/shortcuts/add` (JSON, urlencoded, multipart), `GET /api/shortcuts/summary`, ответы русским текстом, коды ошибок, `Idempotency-Key`/`id`, лимит 60/мин. Рецепты — `SHORTCUTS.md`.
- **Клиент (PWA):** вход (выпадающий список), Лента (по дням, поиск, правка, удаление), Отчёты (кольцевая диаграмма, список категорий, получатели с выбором категории), Добавить, Ещё (импорт, категории/правила, экспорт, быстрые команды, синхронизация, тема, устройства, пароль), нижняя панель, тёмная OLED/светлая темы, safe-area, `viewport-fit=cover`, apple-touch-icon 180×180 без прозрачности, manifest, `prefers-reduced-motion`, поля ≥16 px.
- **Офлайн-очередь:** IndexedDB, идемпотентные id, видимая причина сбоя и время следующей попытки, backoff с jitter (5 с → 15 мин), приоритет `Retry-After`, без опроса по таймеру, шифрование (AES-GCM) при выходе.

## Не проверено / не сделано (честно)
1. **Физический iPhone и Safari не проверялись.** WebKit в среде недоступен; браузерные тесты — Chromium с эмуляцией iPhone. Не проверено: установка «На экран Домой», поведение cookie `Secure/SameSite=Strict` в iOS PWA, динамический остров, жесты, клавиатура, раздельное хранилище Safari и установленного приложения, safe-area на железе, реальный вид иконки.
2. **Боевой Cloudflare:** `wrangler`/`workerd` не запускались, `wrangler deploy`, создание D1 и миграции не выполнялись (нужны действия владельца — README). Тесты шли на `node:sqlite` через адаптер D1; расхождения с настоящим D1 возможны. `wrangler.toml` содержит заглушки `database_id` и `APP_ORIGIN`. Production-сборка Worker (`wrangler deploy --dry-run`) не проверялась.
3. **`git push` не выполнен:** репозиторий владельца не указан. Коммиты — локально (см. ниже).
4. **Профили банков:** Kaspi Gold / депозит и Halyk PDF поддержаны для изученных макетов. Freedom PDF выключен: привязка многострочных деталей и блокировок не доведена до надёжного результата. XLSX и банковские CSV не поддержаны: таких образцов нет. Универсальный CSV сохранён. Подробности — раздел «Профили банков» в DECISIONS.ru.md.
5. **Команды на реальном iPhone не собирались;** `.shortcut`-файла нет. Рецепты написаны по документации действий iOS; триггер «Транзакция Wallet» для карт казахстанских банков не проверялся.
6. **Не реализовано:** Web Push (только архитектурное место), выгрузка в Google Sheets (есть лишь интерфейс `Exporter`), офлайн-правки/удаления, мультивалютность, ограничение числа аккаунтов, тест нагрузки в реальной базе.
7. **Список категорий по умолчанию составлен заново:** старого проекта в папке не было, сверки не было.
8. Автоопределение колонок при импорте — по названиям заголовков (дата/сумма/получатель/описание); для нестандартных заголовков выбор вручную.
9. Известное ограничение дедупликации импорта описано в `DECISIONS.md` (п. 11–12).
10. Название `Қаржы`/`qarjy` — рабочее.

## Как проверить самому
`npm install && npm run build && npm test && npm run test:e2e` (Windows: `npm.cmd`). Для запуска вручную: см. `README.md`. После деплоя — `npm run verify-deployment -- <origin>` и ручной проход по сценариям: вход, добавить, импорт, ключ в «Командах».


## Обновление: профили PDF, 02.11.2026

Kaspi Gold / депозит и Halyk — готовые профили с выбором банка без ручного указания колонок, PDF загружается base64 на сервер. «Проверить» не пишет записи; «Импортировать» возвращает полный отчёт. Freedom остаётся неподдержанным по причинам выше. Автоматического выбора банка нет.

Дедупликация использует прежний ключ с порядковым номером, поскольку уникальный ID операции в поддержанных таблицах не подтверждён. Повтор идентичного файла проверен; идеальная дедупликация пересечений с неразличимыми операциями не гарантирована, возможны совпадения Gold и депозита. Получатели Halyk сохраняют технические префиксы банка, если выделить имя надёжно нельзя. Все неизвестные варианты статусов не заявлены поддержанными. PDF-отчёт считает текстовые строки под шапкой; продолжения описаний видны как отклонённые служебные строки, их текст сохранён в note.

Физический iPhone, Safari и боевой Cloudflare не проверялись. CPU, память и сборка PDF-парсера в настоящем Worker не измерены; локальные проверки используют Node и SQLite. Живые записи, push, деплой и миграции на боевой базе не выполнялись.


Проверки обновления: typecheck — чисто; Vitest — 39/39; build — JS 58,93 КБ gzip; Playwright — 12/12 в каждой из двух конфигураций iPhone (Chromium, CHROMIUM_PATH на установленный Chrome); scan-secrets — 0 находок. Перед e2e исправлен dev-server: fileURLToPath корректно обрабатывает пробелы в Windows-пути.

Дополнительно выполнено локальное сравнение идентификаторов и строк имён из исходных PDF с кандидатами в git и текстом синтетических PDF: совпадений не найдено. Содержимое выписок не включалось в вывод этой проверки. files_for_train/ игнорируется и не отслеживается. Это дополнительная эвристическая проверка, а не доказательство отсутствия любых возможных персональных данных.
