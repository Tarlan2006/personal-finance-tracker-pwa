# Аудит кнопок, жестов и анимаций Qarjy — 04.11.2026

Проверяется версия после `2232161`. Все изменяющие сценарии выполняются только локально, на вымышленных аккаунтах и SQLite/D1. Банковские PDF — синтетические фикстуры. Реальные выписки и боевые финансовые аккаунты в аудит не входят.

## Короткая проверка на iPhone

Для удаления используйте специально добавленные тестовые операции.

1. Обновите Qarjy, откройте длинную ленту и прокрутите вниз. Запомните видимую оставляемую карточку.
2. Сделайте обычный свайп: лента прокручивается, выбор не включается. Короткий тап открывает редактор; закройте его.
3. Удерживайте карточку около 0,5 секунды: появляется одна отметка и чекбоксы, редактор не открывается.
4. Выберите ещё две карточки, снимите одну отметку. Проверьте счётчик. «Отмена» снимает режим выбора.
5. Повторите выбор, нажмите «Удалить», сначала отмените подтверждение: операции остаются. Затем подтвердите удаление тестовых операций.
6. Оставшаяся видимая карточка сохраняет место на экране, лента не прыгает к началу; «Показать ещё» работает. У физически короткого/пустого списка прежняя позиция ограничена его новой высотой.

Повторите в светлой/тёмной теме и установленной PWA. На устройстве отдельно проверьте, не появляется ли системное меню выделения/копирования при long press, и поведение клавиатуры.

## Найдено и исправлено

- Панель выбора z-index:40 перекрывала шторки z-index:21, особенно на коротком экране. Панель перенесена под modal; шторки учитывают порядок открытия, Escape/Tab обрабатывает верхняя.
- Удаление правила/отзыв ключа/отзыв устройства и первичная загрузка правил могли оставить необработанный Promise при отказе сети. Действия показывают ошибку и допускают повтор/обновление списка.
- Несколько форм принимали повторную отправку до обновления React busy-state. Добавлен синхронный guard: вход, анкета, редактор, категории, правила, ключи, пароль и выход; изменяющие кнопки/поля и закрытие шторки блокируются до завершения.
- Кнопка копирования молча скрывала отказ/отсутствие clipboard. Теперь есть явная ошибка с ручным способом копирования и «Скопировано» только после успешного API-вызова.
- Лента не перечитывала очередь при pending→failed с прежним count. Теперь отказ и кнопка «Убрать» появляются сразу; ошибки локального удаления/повторной отправки показаны без pageerror.
- Форму добавления можно было закрыть во время долгого сохранения IndexedDB; поздний onDone мог закрыть следующую форму. Закрытие/поля блокируются, результат размонтированной формы не закрывает новую.
- CSV-переключатели оставались активными во время проверки. Ввод mapping/режимы блокируются до ответа; удаление истории при активном импорте также явно disabled.
- У маленьких кнопок/палитры был уменьшенный размер. Малые кнопки, возврат, сегменты и все цвета увеличены до 44 px; панель выбора допускает перенос счётчика на узком экране.

## Границы

Это воспроизводимая проверка реализации на известных сценариях, а не обещание отсутствия любых ошибок. Физический iPhone, системные long press/инерция/выделение текста, настоящий picker/iCloud, экранная клавиатура/VisualViewport, VoiceOver, установка/обновление домашней PWA, системный режим блокировки и выгрузка ОС требуют устройства. WebKit на Windows и Chromium с мобильной эмуляцией не заменяют эти проверки. Живые финансовые записи и реальные выписки не используются.

## Повтор проверки

После установки зависимостей и браузеров, на Node из engines:

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
npm.cmd run test:safari
npm.cmd run test:import-runtime
npm.cmd run scan-secrets
```

Новый целевой аудит: `npx.cmd playwright test tests-e2e/ui-audit.spec.ts --project=webkit-iPhone-light` (аналогично остальные три проекта). Полные проекты запускаются штатными npm-скриптами по отдельности на свежих базах: существующие сценарии изменяют пароль/анкету тестового owner. Не пересобирать web/dist во время браузерного прогона.

Проверка SW больше не заменяет controller до завершения первоначального запуска приложения. После обнаруженной гонки добавлено ожидание экрана входа до ручной регистрации, проверка pageerror сохранена без фильтров. Все три режима отказа кэша отдельно повторены пять раз в WebKit — 15/15; затем повторены полные прогоны.
