# Локальный аудит Qarjy · 24 ноября 2026

Рабочая копия включает изменения BankLogo поверх `0d7366b`. Все данные прогона созданы специально для аудита. Использованы SQLite в памяти, локальная сборка Vite и тот же обработчик Worker, который вызывает сервер разработки. Внешние аккаунты, D1 и сайт в проверке не участвовали.

## Сверка расчётов

`node_modules/.bin/tsx scripts/audit-ledger.ts` создаёт отдельную SQLite в памяти. Набор включает 251 обычную операцию и один перевод. Одну обычную операцию скрипт мягко удаляет. В экспорт попало 250 строк. Начало учёта — 1 января; набор охватывает миллисекунды до границы, на границе и после неё, данные до открытия, текущий и предыдущий месяцы, завтрашнюю дату, один тиын и максимально допустимую сумму одной операции.

Скрипт читает исходные строки SQLite, считает со знаком в BigInt и задаёт фиксированный сдвиг даты самостоятельно. Функции агрегации приложения для получения эталона не используются. Сверены три остатка, доходы и расходы по каждому счёту, количество операций без счёта, месячные итоги, суммы категорий и получателей, сумма и количество без категории, порядок топ-10, CSV и текст сводки «Команд». Для ноября 2026 получились 20 комбинаций — четыре месяца и пять вариантов фильтра. В тесте браузера данные создаются заново через API, с локальными ID категорий. Проверяются также сумма подписей процентов и длины дуг с учётом графического зазора. Значения на карточке бюджета наличных и в сводке анкеты (сумма начальных остатков, план расходов, ежемесячные накопления и сумма цели) сверены с JSON профиля, отдельно прочитанным из SQLite.

Планы анкеты отображаются как введённые значения. Автоматической привязки покупок к плану и алгоритма накопления по цели в текущей модели нет. Переход категории задним числом, снятие привязок, перенос на другой счёт, повтор запроса, отмену перевода и отчёт по четырём статусам импорта дополнительно покрывают интеграционные тесты. Если источник не назначен, две внешне одинаковые выписки без счёта по-прежнему неразличимы по финансовому счёту.

## API, офлайн и стоимость запросов

В маршрутизаторе 45 сочетаний метода и пути. Три публичных обработчика обслуживают здоровье сервиса, вход и разрешённые варианты логина. Два маршрута «Команд» проверяют область ключа. Для остальных сорока маршрутов контекст аккаунта берётся из сессии. Параметризованная проверка обходит все 42 закрытых маршрута без учётных данных и сверяет ответ 401. Для каждой изменяющей операции сессии она также проверяет, что явно переданный чужой accountLogin даёт 409 до записи. Глобальные профили форматов импорта не содержат финансовых данных. В наборе есть проверки чужих ID, несовпадения `accountLogin` на изменяющих маршрутах, типов запросов, Origin, версий, повторных операций и пакетных подтверждений удаления. Совместимые клиенты могут не передавать `accountLogin` для части обычных записей; SQL всё равно ограничен аккаунтом сессии.

Хеши паролей рассчитываются PBKDF2 с солью, в таблицах сессий и API-ключей сохраняются хеши токенов. Cookie имеет HttpOnly, Secure и SameSite=Strict. Проверка Origin сравнивает присутствующий заголовок с origin запроса. Порог последовательных ошибок входа — пять, блокировка на 15 минут. Очистка служебных записей ограничена порцией и запускается после входа; финансовая история и история ключей для восстановления очереди могут расти. Проверены отказ IndexedDB, восстановление очереди после входа и смены пароля, повтор отправки без дубликата. Рабочая очередь авторизованной сессии локально доступна открытой; шифрование применяется при выходе. Клиент не загружает списки финансов по таймеру.

`X-Storage-Ops` считает обращения адаптера. Число физических чтений строк, биллинговый показатель rows_read, CPU и пиковая память D1 этим числом не измеряются. Локальный `npm ls --omit=optional --all` прошёл. Свежая внешняя база уязвимостей не запрашивалась. Сканер секретов проверяет файлы по правилам проекта; результат не является проверкой всех возможных форматов секретов.

## Интерфейс и границы проверки

Сценарии покрывают вход и выход, шаги анкеты, выбор банка и счёта, карточки кошелька и сброс выбора, формы, бюджет и перевод, выбор операций кликом и долгим нажатием, поиск, категории и правила, месяцы, сектора диаграммы и повторный выбор, справочник получателей, импорт, историю пакетов, CSV, устройства, ключи, пароль, синхронизацию. Отдельные UX-сценарии проверяют размеры целей касания, CSS-контраст токенов относительно фонов, масштаб текста 200%, фокус, геометрию при уменьшенном VisualViewport, прокрутку и восстановление после ошибок.

Старт `npm run dev` подтверждён. TCP-соединение с 127.0.0.1 и ::1 блокировалось как для Node, так и для Chromium. Для проверок экрана Playwright передавал запросы того же origin непосредственно локальному Worker с SQLite и отдавал файлы из `web/dist`. Прямой транспорт, обработка защищённой cookie на физическом телефоне, системный менеджер загрузок и сетевые события при работе реального SW требуют отдельной проверки. Ожидаемые ошибки намеренно отключённой сети анализировались отдельно от успешных сценариев. Покрытие кнопок сценарное; исчерпывающего доказательства для каждой комбинации кнопки, пользователя, размера и состояния нет.

Физический iPhone, реальная iOS-клавиатура, вырез экрана и системный safe area, нативные Siri/«Команды», браузерная установка на домашний экран, производственные лимиты Cloudflare и межрегиональные гонки D1 не проверялись. Деплоя, пуша и обращения к рабочим финансовым данным не было.
