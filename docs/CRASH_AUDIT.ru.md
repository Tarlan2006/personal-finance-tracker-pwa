# Аудит и краш-тест Qarjy — 02.11.2026

Проверялась реализованная функциональность, а не возможность всех теоретических атак. Разрушительные сценарии выполнялись только в изолированных локальных аккаунтах и базах. Реальные выписки не загружались на сайт, боевые операции и анкеты не создавались. На публичном сайте — только проверки без авторизации; публикация результатов указана в STATUS.ru.md.

## Найдено и исправлено

| Проблема | Исправление и подтверждение |
|---|---|
| Публичный список логинов и имён клиентов | GET /api/accounts требует сессию и возвращает только текущий аккаунт. Вход через поле логина, с нормализацией пробелов/регистра в клиенте. Отдельный тест анонимного доступа и изоляции. |
| POST login принимал чужой Origin / неподходящий Content-Type | Общая проверка Origin/JSON, в том числе при входе. Проверка 403 на чужой Origin. Ключевые маршруты «Команд» сохранили свои форматы. |
| JSON null, неверные типы, неправильный URL и дробный limit вызывали 500 | Объектный JSON, проверка полей, дат, query и направлений до SQL. URL-декодирование возвращает 400. Некорректные элементы batch получают отдельные ошибки и не останавливают остальные. |
| Несуществующая дата могла нормализоваться Date.parse в следующий месяц | Календарная проверка, целые UTC-миллисекунды, отдельная поддержка ISO с часовым поясом. 31 февраля и дробные миллисекунды отвергаются. |
| Тело без достоверного Content-Length полностью читалось до проверки лимита | Поток останавливается и отменяется при превышении байтового предела; тест подтверждает раннюю отмену потока. |
| Незакрытая CSV-кавычка поглощала следующие строки | Весь повреждённый CSV отклоняется до финансовой записи. Ранние пределы 1000 строк и 256 колонок; значения mapping проверяются. |
| Старый запрос мог продолжать очередь после выхода/смены аккаунта | Поколение очереди, остановка таймера и проверки перед отправкой/обработкой ответа. Сценарий: удержать первую пачку из 50, выйти, войти в другой аккаунт, вернуть ответ, затем восстановить владельцу все 51 записи. В чужом аккаунте ноль таких операций. |
| Запоздалый 401 старой сессии мог сбрасывать новый вход | Поколение сессии в API-клиенте, тест с задержанным 401 после нового login. |
| Запрет IndexedDB приводил к необработанным Promise и блокировал вход | Онлайн-вход продолжается; очередь сообщает недоступность, добавление показывает ошибку и не обещает сохранение. Тест подменяет IndexedDB на SecurityError, проверяет отсутствие pageerror. |
| Двойной submit мог создать две новые операции | Синхронный ref-флаг формы; два submit в одном событии дают одну операцию. Аналогичная защита в создании категории. |
| Старый ответ отчёта мог подменять выбранный месяц | Результаты принимаются только активным эффектом; тест задерживает ответ текущего месяца и переключается на предыдущий. |
| Медленное чтение файла могло вернуть старый файл после смены банка | Поколение чтения, обработка ошибки File.arrayBuffer и отмена результата при смене банка/размонтаже. |
| UI показывал только первые 100 отклонённых/дублирующихся строк | Постраничная кнопка «Показать ещё строки отчёта», проверены все 150 отклонённых строк. Полный серверный отчёт не изменён. |
| Неверная сумма в анкете исчезала при переходе «Назад» | Переход проверяет валидность перед размонтированием поля; исправленная сумма и выбор категории сохраняются. |
| На шаге расходов не было создания своей категории | Кнопка «+ Добавить категорию», шторка названия/цвета, немедленное появление в списке и автоматический выбор. Повторное название отклоняется. |
| Параллельное создание одинаковых категорий давало дубли | Одинаковые нормализованные названия выделяют один свободный хеш-ID; SQL проверяет снимок имён перед записью. Конкурентные create/create, rename/rename и create/rename дают одну запись и 409 второму изменению. Удалённые и переименованные ID не переиспользуются: новая категория не оживляет старую историю. |
| API обрезал длинные названия/описания; категория могла переименоваться в уже существующую | Некорректные типы/длины возвращают 400, обычная коллизия имени при переименовании — 409. |
| Экстремальный месячный итог мог потерять точность тиынов | Проверка safe integer при суммировании; ответ 422 вместо округлённого числа. Тест 1000 максимальных операций. |
| Ошибка хранилища могла выводить подробности исключения в журнал и не иметь счётчика | Общее сообщение журнала без параметров, X-Storage-Ops сохраняется и для 500. |
| npm audit: 6 уязвимых dev-пакетов (3 moderate, 1 high, 2 critical) | Vite 8.3.5, Vitest 5.0.5, React plugin 6.2.1, чистый lockfile без --force/legacy-peer-deps. Аудит после установки — 0. Production-зависимости не изменились. Node: 22.12 LTS / 24 LTS либо поддерживаемый более новый чётный релиз. |

## Предсказуемые данные

`tests-e2e/fixtures/crash-scenario.json` содержит только вымышленные значения. Семь счетов: карта и депозит каждого из трёх банков плюс наличные, ожидаемая сумма 2 800 000 тиынов. CSV: два одинаковых расхода по 10 025 тиынов, доход 100 000 и несуществующая дата. Ожидание: total 4, imported 3, rejected 1; расход 20 050, доход 100 000. Повтор: 0 новых, 3 duplicate, 1 rejected. Внутри файла две одинаковые операции сохраняются отдельно.

Дополнительно: 30 счетов и удаление одного без изменения соседней суммы; неизвестный остаток отличается от нуля; создание/дубликат категории; 150 отклонённых строк; две сессии и очередь из 51 операции; двойная отправка; потеря сети, блокировка локального хранилища, задержка файлового чтения и ответов отчётов. Дополнительные seed-аккаунты существуют только в dev-server и тестовой конфигурации, не входят в Worker.

## Границы проверки

Не проверены физический iPhone, Safari/WebKit, VoiceOver, реальная клавиатура и обновление установленной PWA; боевые CPU/память/суточные квоты D1 и нагрузка множества пользователей. Это не пентест всей инфраструктуры Cloudflare. Авторизованные разрушающие сценарии на боевой базе не выполнялись. Нулевой npm audit означает отсутствие известных находок в текущем реестре, а не доказательство отсутствия всех уязвимостей.

Прежние продуктовые ограничения сохраняются: KZT, изученные текстовые PDF-макеты, неоднозначная дедупликация одинаковых операций без банковского ID, отсутствие привязки операций к отдельному счёту и вычисления актуального баланса, офлайн-правок/удалений, автоматических платежей и прогресса целей. Начальные остатки и планы не считаются доходами.


## Итог проверки

Typecheck, 75 Vitest, полный Playwright 58/58 (29 × 2 темы), сборка и scan-secrets зелёные. Дополнительно 34 проверки локального workerd/D1, включая конкурентные категории и неизменённую атомарность 1000 строк. npm audit — 0 находок. JS 66,80 КБ gzip, CSS 4,59 КБ gzip. В локальном сравнении характерных имён/идентификаторов личных PDF с исходниками и текстом публичных фикстур совпадений нет; files_for_train/ игнорируется и не отслеживается. Это эвристическая проверка приватности.

При проверке Retry-After также исправлены блокирование выхода клиентской паузой и перенос 429 между сессиями. Два отдельных теста подтверждают разрешённый logout, сброс локальной паузы при login и игнорирование запоздалого 429. Серверный лимит входа сохранён.
