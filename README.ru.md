# Қаржы (рабочее название `qarjy`)

Личный трекер доходов/расходов для iPhone (PWA) + интеграция с «Командами». Cloudflare Worker + D1, клиент React/Vite. Основа готова; поддержаны изученные PDF-макеты Kaspi Gold / депозита и Halyk. Freedom PDF поддержан по изученному макету Letter; ограничения — docs/DECISIONS.ru.md.

## Что есть
Аккаунты и сессии, отзыв устройств, ключи API (`write`/`read`), эндпоинты для «Команд» ([docs/SHORTCUTS.ru.md](docs/SHORTCUTS.ru.md)), ручной ввод, категории (редактируются), привязка получателей к категориям, правила по тексту, импорт CSV с отчётом по каждой строке, отчёты по категориям и получателям, экспорт CSV, офлайн-очередь с диагностикой. Решения — в [docs/DECISIONS.ru.md](docs/DECISIONS.ru.md), итог и непроверенное — в [docs/STATUS.ru.md](docs/STATUS.ru.md).

## Команды (Windows: `npm.cmd` / `npx.cmd`)
```
npm install
npm run build        # клиент в web/dist
npm run typecheck
npm test             # Vitest: сервер/клиент, реальный SQLite
npm run test:e2e     # Playwright, эмуляция iPhone, тёмная и светлая тема
npm run scan-secrets
npm run ops-report   # обращения к хранилищу на типичный сеанс
npm run dev          # локальный сервер http://localhost:8787 (память; DB_FILE=файл.sqlite для файла)
```
Для `test:e2e` в среде без стандартной установки браузеров можно указать `CHROMIUM_PATH` (путь к chromium). Установленный Playwright: `npx playwright install chromium`.

## Локальный запуск с аккаунтом
```
npm run build
set DB_FILE=.wrangler\dev.sqlite
set SEED_ACCOUNT=owner:ВашПарольНеМенее10Символов     (только для локальной разработки)
npm run dev
```
Либо создайте аккаунт скриптом: `npm run accounts -- add owner "Владелец" --db .wrangler/dev.sqlite` (пароль вводится скрыто; в базе должны быть применены миграции — их применяет dev-сервер при запуске с новой или существующей базой).

## Деплой (шаги для владельца — ничего боевого не выполнялось)
1. `npx wrangler login`
2. Создать базу: `npx wrangler d1 create qarjy` → скопировать `database_id` в `wrangler.toml`.
3. Применить миграции: `npm run migrate:remote` (локально: `npm run migrate:local`).
4. `npm run build && npx wrangler deploy` → получите адрес `https://qarjy.<субдомен>.workers.dev`; впишите его в `wrangler.toml` → `APP_ORIGIN` (его проверяет админ-скрипт).
5. Создать первого пользователя:
   `npm run accounts -- add owner "Владелец" --remote --confirm-origin https://qarjy.<субдомен>.workers.dev`
6. Проверка (только публичные GET): `npm run verify-deployment -- https://qarjy.<субдомен>.workers.dev`
7. На iPhone: Safari → открыть адрес → «Поделиться» → «На экран „Домой“».
8. Репозиторий: создайте новый пустой репозиторий на GitHub и выполните `git remote add origin <URL>` и `git push -u origin main` (без `--force`).

После деплоя проверьте вручную то, что тесты на SQLite не покрывают: вход, добавление записи, импорт небольшого CSV, чтение/запись ключом.

## Админ-скрипт `scripts/accounts.ts`
`add`, `set-password`, `list`, `revoke` (устройства и ключи), `disable`, `enable`. Цель — `--db <файл sqlite>` или `--remote --confirm-origin <origin>` (должен точно совпасть с `APP_ORIGIN`). Для автоматизации пароль можно передать переменной `QARJY_PASSWORD`.

## Структура
`migrations/` — SQL; `worker/src/` — ядро (`auth.ts`, `index.ts`, `ratelimit.ts`) и `domain/money/` (домен); `worker/dev/` — адаптер D1→SQLite только для тестов/dev; `web/src/` — клиент; `scripts/` — админ, dev-сервер, сканер секретов, проверка деплоя; `tests-e2e/` — Playwright.

## Куда добавлять банк
Профили лежат в `worker/src/domain/money/import.ts` (`BANK_PROFILES`). После получения образца: добавить функцию, которая приводит выписку к `Mapping` (или разбирает формат), включить `ready: true`, написать тест на образце, чтобы сошёлся инвариант «каждая строка учтена».


## Безопасный объём импорта

Один импорт — максимум 1000 строк (для Kaspi/Halyk включая продолжения и служебный текст под шапкой; для Freedom — логические строки операций). Более длинную выписку разделите по непересекающимся датам, не разбивая одинаковые операции одного дня. День, который целиком превышает лимит, этим импортом не поддержан. Сохранение операций, получателей и отчёта атомарно: SQL-ошибка не оставляет частичный импорт. При потере ответа повторите файл — уже сохранённые операции будут дублями.

Дополнительная локальная проверка перед выпуском: `npm.cmd run test:import-runtime`. Она запускает отдельный workerd с синтетической D1, не использует боевую базу и не делает деплой. Первый запуск загружает Wrangler из npm. Проверки на личных исходниках без записи данных: `npx.cmd tsx scripts/audit-bank-samples.ts` (Python с pypdf; путь задаётся AUDIT_PYTHON).

## Стартовая финансовая анкета

После первого входа Qarjy предлагает пять шагов: банки и отдельные счета/депозиты/наличные с остатками на выбранную дату; категории расходов и месячный план; источники и регулярность доходов; обязательные платежи и долги; финансовая цель и накопления. «Сохранить и продолжить» сохраняет черновик на сервере; «Сохранить и заполнить позже» открывает приложение. Продолжить или изменить ответы можно в «Ещё → Финансовый профиль».

Суммы только в KZT. Пустая сумма означает «не указано», ноль — указанный нулевой остаток. Начальные остатки и планы не создают доходов/расходов. Связь операций с отдельным банковским счётом и вычисление актуального остатка по нему пока не реализованы. Выбранные категории выводятся первыми в добавлении операции; банк из профиля выбирается по умолчанию в выписке.

Для запуска этой версии нужна новая миграция `0003_financial_profiles.sql`. Существующие миграции не изменены. Данные анкеты доступны только в авторизованном аккаунте. Не собираются ИИН, номера карт, CVV и банковские пароли; не вводите их в свободные поля. Ответы не отправляются в ИИ. Это информация для настройки личного финансового учёта, без автоматических банковских подключений.

## Вход и собственные категории

Входите по логину и паролю: список имён клиентов больше не публикуется. Логины и пароли существующих аккаунтов не менялись. На шаге анкеты «Расходы» доступна кнопка «+ Добавить категорию»: название и цвет, новая категория сразу отмечается в списке.

Для разработки используйте Node 24 LTS (также поддерживается Node 22.12+ по engines package.json). Инструменты сборки и тестов обновлены; проверка зависимостей: `npm audit`. Протокол краш-теста и ограничения: [docs/CRASH_AUDIT.ru.md](docs/CRASH_AUDIT.ru.md).
